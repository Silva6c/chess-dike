# 连线功能说明（屏幕识别 · 悬浮窗走法指导）

## 功能定位

本功能是"象棋迪克"（开源免费安卓版中国象棋学习工具）的连线模块，参考了桌面端象棋连线器
（VinXiangQi 及其衍生 XiangQiLink）的思路，把"屏幕识别 → 引擎分析 → 提示建议"搬到 Android 上：

1. 用系统录屏授权（MediaProjection）只读截取当前屏幕画面；
2. 用深度学习模型识别画面中的 9×10 棋盘局面——**双引擎**：默认 **ONNX 两步式**
   （RTMPose 检测棋盘四角 + Swin 逐交叉点分类 16 类），对未收录的棋盘皮肤泛化更好；
   模型缺失或加载失败自动回退 **YOLOv5 检测式**（14 类棋子 + 整体棋盘框）。
   两种引擎都**免校准、免采集**，兼容天天象棋 / JJ 象棋 / 自研棋盘等不同画风；
3. 自动判定**靠近玩家一侧（屏幕下方阵营）就是我方**，并识别我方执红还是执黑（含换边局）；
4. 复用项目内嵌的 pikafish 引擎对当前局面进行分析；
5. 在**悬浮窗**中显示：**原版样式的微缩棋盘**（与主界面同一套棋盘/棋子图，随被识别屏幕的朝向显示，
   底部永远是我方一侧）、我方最佳走法（如"炮二平五 (h2e2)"）以箭头标注在迷你棋盘上、
   红/黑优劣势与深度、候选着法与变着；
6. **悔棋**：点"悔棋"可回退到上一个已确认局面重新分析（看上一手之前的建议），
   再点"继续"恢复实时识别；**引擎强度**：深度制下点"深度"在 深度12（快速）/
   深度20（标准，默认）/ 深度24（强劲）三档间循环，档位会记住；连线页切到
   **时间制**后悬浮窗改显示"时间"芯片（1/2/3/5/10/30 秒循环）。
   档位与速度的机制关系：**变招 2-3 路**会分散根节点搜索（同深度约慢一半，换取
   备选候选展示）；**时间制**每步固定烧满设定时长（深度制简单局面可秒收）——
   切换档位时悬浮窗会提示对应代价。

识别只服务于"我方"：**靠近玩家的一侧给建议**；对方回合引擎的算力同样为我方所用——
展示"若对方走X，我方应Y"的应对预案（箭头画我方应手），我方走子确认后立即转入新局面计算。
引擎不做（也不需要做）任何干扰对方的操作。

## 为什么它不是外挂（合规说明）

本项目是大作业/学习用途，明确不做任何作弊功能，也刻意避免"外挂特征"：

| 本项目 | 拒绝的做法（典型外挂特征） |
| --- | --- |
| 只通过系统录屏授权"看"画面 | 触摸/手势注入（AccessibilityService dispatchGesture、注入 MotionEvent） |
| 只显示建议文本与箭头，走子由玩家手动完成 | 自动点击、自动走子、自瞄 |
| 仅申请 SYSTEM_ALERT_WINDOW 悬浮窗与录屏两个常规权限 | 无障碍服务、Root/Xposed/注入插件、读写他人 App 内存与文件 |
| 识别结果经"稳定帧校验+合法性校验+迷你棋盘回显"保证正确 | 实时屏下"注入式"操作，无用户可核对依据 |

权限一览：`SYSTEM_ALERT_WINDOW`（悬浮窗，与微信/输入法同类）、
`FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MEDIA_PROJECTION`（录屏式前台服务）、
`POST_NOTIFICATIONS`（前台服务通知）、`INTERNET`（**唯一网络用途**是连线页"检查更新"
按钮手动查询 GitHub 新版本元数据——不自动检查、不内置下载，识别/引擎/开局库/帮助页
全部本地完成）。**未申请** `BIND_ACCESSIBILITY_SERVICE`、`QUERY_ALL_PACKAGES`、
`REQUEST_INSTALL_PACKAGES` 等敏感权限。

## 首次使用步骤（真机验证清单）

1. 打开应用（启动即连线功能页，无中间主页）；
2. ① 在弹出的系统设置中允许悬浮窗权限；② 允许通知（Android 13+）；
3. ③ 点击"开始屏幕识别"，在系统录屏授权对话框选"开始录制/立即开始"（Android 14 需再次确认）；
4. 切到任意象棋 App 的对局界面即可——**识别全自动**：自动找棋盘、自动判定朝向
   （红上/红下）、自动开始识别。悬浮窗出现在屏幕底部（不遮挡棋盘），显示迷你棋盘与建议；
5. 常用按钮：状态栏大字（建议/优劣势/轮次信息，一眼可读）、左下一行 **变招**（切换候选着法，
   点迷你棋盘同效）、**悔棋**（回退一步，点"继续"恢复实时）、**手动**（紧急手动模式，见下）；
   右列 **深度**（深度制：12 快速 / 20 标准（默认） / 24 强劲）或 **时间**
   （时间制：1/2/3/5/10/30 秒，随连线页制式二选一显示）、**Hash**（引擎置换表
   大小，从 256MB 起循环 256→512→1024→2048，对下一次搜索生效）、**闪电**（打断当前
   搜索、立即采纳当前最优着法）、**更新棋局**（显示的行棋方与实际不符时点一下立即纠正）、
   **停止**、**关闭**（需二次确认：先变“确认关闭?”，3 秒内再点才真正关闭，误触有缓冲）。
   我方颜色自动判定（屏幕下方阵营=我方），无需手动切换。

## 紧急手动模式（识别失效时的兜底）

个别对局界面（如某些残局/特殊皮肤）识别可能临时失效——状态栏持续显示“正在识别棋盘…”或
迷你棋盘出现明显错子。此时点 **手动** 进入紧急手动模式：自动识别暂停，由你在迷你棋盘上手工
维护局面，引擎/开局库继续给建议：

- **录入着法**：点我方或对方的子（金色高亮）→ 点目标格，等同实战走了一步，行棋方自动翻转；
- **删子**：点一下已选中的子再点它自己，即从盘面删除（用于清除“幻影棋子”；帅/将不可删）；
- **悔棋**可逐步撤销手工编辑；**更新棋局**可纠正行棋方；**变招/深度**照常可用；
- 再点一次 **手动** 即恢复自动识别（识别恢复后会自动接手工局面继续跟踪）。

附注：识别全自动，悬浮窗与连线页均无"校准"按钮（手动校准系统已随本版本移除）；
识别模型内置于应用（ONNX 角点 + 分类共约 21.5MB，YOLO 回退模型约 3.8MB，随应用安装，
无需联网）。

## 性能与发热须知（重要，请先读）

本应用是**全离线单机**方案：屏幕采集、棋盘识别、引擎搜索全部在手机上完成。连线期间同时有三路负载：

1. **屏幕采集与像素转换**：整屏 RGBA→ARGB 每帧约 246 万像素（静止画面零推理，
   帧差判静即整帧丢弃）；
2. **棋盘识别**：ONNX 两步式推理（4 线程，角点 + 90 交叉点分类）；回退的 YOLO 也对整帧推理；
3. **皮卡鱼引擎**：搜索线程数 = 手机核心数的一半（给识别与系统留核），深度制下持续计算。

三者抢同一颗 CPU，连线期间负载偏高。因此：

- **机身发热是预期现象**：连续使用（尤其夏季、边充边用、戴厚保护壳）会明显发热，
  这是单机全栈方案的固有代价，不是 Bug；
- **发热会拖慢识别**：温度上来后系统温控自动降频，识别单帧耗时上升 → 局面确认变慢 →
  悬浮窗建议更新滞后；引擎同深度的出着时间也会变长；
- 识别器有**自适应节拍器**（间隔按上一帧实际耗时自动放宽，失败自动退避、硬上限 8s；
  画面一变自动收紧到 300ms 级快速确认；走子动画期间等停稳再识别），降频时不会卡死
  或堆任务，但表现就是"变慢"——这是保护机制在起作用。

**缓解建议**：

- 避免边充边用；摘掉厚壳，或加散热背夹/放在通风处；
- 长时间使用中途点"停止"让手机休息，间歇使用；
- 对节奏敏感时把思考制式切到**时间制**（固定时长收束，不会因降频越搜越久）；
- 需要更轻负载时可把引擎切到 **YOLO**（推理开销更低，精度略逊于 ONNX），或降低深度档。

**如果你的场景是长时间、高强度连续使用**，单机方案的发热与降频无法根治——建议改用
[内阁 Cabinet](https://github.com/Silva6c/cabinet)：引擎跑在电脑端，手机只做采集、识别与
悬浮窗显示，手机几乎不发热，引擎强度也不受手机性能与温控限制。

## 性能诊断（识别变慢时一键采集数据）

如果感觉"识别变慢、建议更新滞后"，不用抓 logcat，连线页自带的诊断开关可直接采数据：

1. 回到连线页，设置区把 **性能诊断** 点成"开"——应用会在系统 **Download 目录**
   新建 `XQDK_诊断_<时间戳>.md`，并弹出提示标明完整文件路径；
2. 切回对局正常使用几分钟（覆盖走子确认、切页、出招等场景）；
3. 再点一下开关成"关"（或退出连线）——文件自动封口收尾；
4. 文件管理器进 Download 目录，把该 md 文件发出去即可。

文件是**综合单日志**，四个小节持续并写（开关打开期间不断有产出）：

- **会话**：设备/版本 + 参数快照（识别引擎、搜索制式、变招路数、Hash、确认帧数）；
- **事件**：录屏启动、引擎加载/切换、档位变化、切页清退避、自愈（连续失败清角点
  缓存）、棋盘确认（含 FEN）、服务停止；
- **识别帧**：每次识别一行——时间、间隔（距上帧）、定位方式（全图/复用/复检/YOLO/
  失败）、五段耗时（角点预处理/推理、透视重采样、分类预处理/推理）、总耗时、
  **节拍**（常规/burst 余量/退避倍数）、结果（失败**带原因**：定位失败/棋子过少/
  非法×N 等）；每 20 行自动插一条汇总（成功/失败计数、平均/P50/P95 耗时、平均间隔、
  失败原因分布）；
- **引擎**：皮卡鱼每次深度推进与定着一行——局面、深度、已耗时、首变。

关闭诊断开关即可恢复正常运行（诊断行写入随开关重建引擎后生效，平时零开销）。
数据回来后按五段耗时即可归因瓶颈在哪一段（角点检测 / 透视重采样 / 分类推理），
节拍列与事件节能直接看出"慢的时段处于什么状态"（退避重试 / burst 确认 / 复检），
不用猜测。

**两种"慢"的判读**（拿到 log 先分清是哪一种）：

- **识别慢**（走子后悬浮窗迟迟不刷新）：看"识别帧"节。健康口径：成功帧总耗时
  P50 ≤ 300ms、失败集中在启动段并自动恢复；若 clsRun 列偏高且"引擎"节同一时段
  正在爬深度，属引擎搜索与识别并发争抢 CPU（真机实测搜索中识别单帧涨 2~3 倍），
  引擎定着后即回落，正常现象。
- **出招慢**（局面确认后箭头迟迟不定/不变绿）：看"引擎"节。深度制 20 层中局
  定着 2~7 秒属正常；要更快可点悬浮窗"深度"按钮降到 12 层，或连线页改时间制
  1~3 秒。注意：**变招路数只影响出招速度，不影响识别**——2/3 路附带备选候选
  的代价是同深度搜索约慢一半。

## 变招路数（MultiPV，默认 1 路）

悬浮窗"**N变**"按钮循环 1→2→3 路：1 路把全部算力集中最佳着（最强，**默认**）；
2-3 路附带备选候选，代价是同深度搜索约慢一半——要看备选再手动开。

## 检查更新（手动，不自动检查）

连线页设置区的 **检查更新** 按钮手动触发——应用**不会**自动检查更新（无启动自检、
无后台联网）。点击后查询 GitHub 上的正式发布版本（`v3.2` 等语义化版本 tag，旧
`stable-YYYYMMDD` 日期版同样兼容），与当前构建日期比较：

- **发现新版本**：弹窗显示最新版号，点"打开下载页"跳转 GitHub Release 页面，
  手动下载安装 APK（需要可访问 GitHub 的网络环境；下载的包与已装包签名不同时
  需卸载重装）；
- **已是最新**：Toast 简短提示；
- **查询失败**：Toast 提示原因（超时/被限流/网络不可达）——中国大陆直连
  api.github.com 通常不可达，需挂可访问 GitHub 的网络环境后重试。

应用内置的引擎/模型/开局库全部离线工作，检查更新是唯一的联网行为，且仅在你
主动点击时发生、只查询版本元数据、不自动下载任何内容。

## 技术要点（答辩速览）

- **识别管线（默认 ONNX 两步式）**：屏幕帧 → RTMPose 检测棋盘四角（全图外扩 1.25 倍
  仿射到 256×256，SimCC argmax 解码后逆仿射回原图）→ 单应透视到 450×500 俯视图
  （四角固定落 (50,50)/(400,50)/(50,450)/(400,450)）→ Swin 对 90 个交叉点逐点分类 16 类
  （空 / 未知 / 红七子 / 黑七子）→ 局面。角点命中会话网格时缓存复用、超 8 秒强制
  全图复检，连续 3 帧结构非法（走子动画过渡帧）同样强制重定位；几何与解码为纯 JVM
  实现（`OnnxGeom` / `OnnxBoardRecognizer`），可单测；
- **回退管线（YOLO 检测）**：ONNX 模型缺失或加载失败时自动切换——屏幕帧 letterbox 到
  640×640 RGB → TFLite 运行 YOLOv5n（15 类：14 种棋子 + 棋盘框）→ 解码 + 类别感知 NMS
  → 置信度/宽高比/尺寸一致性过滤（排除工具栏按钮、"轮到谁"标记盘等误检）→ 棋盘框
  宽/8、高/9 得到格距，棋子中心 round 到最近交叉点 → 帅/将位置判屏幕朝向（红在下/红在上）
  → 镜像映射到内部"红恒在下"坐标系 → 数量/将帅/上限合法性校验；
  解码、过滤与棋盘映射为纯 JVM 实现（`YoloPostprocessor` / `DetectionBoardMapper`），可单测；
- **稳定性**：连续 N 帧（默认 3）识别结果一致才确认新局；动画/选中态造成的跳动帧被丢弃；
  新对局（回到开局）自动重置轮次；已知棋盘位置后裁剪推理，若棋盘挪动导致残框内长时间
  不稳定会自动回退全屏重新定位；
- **我方颜色判定**：屏幕下方阵营＝我方；下方是红→我方执红，下方是黑（换边局）→我方执黑，
  完全自动（迷你棋盘朝向随动，底部恒为我方一侧）；
- **轮次(w/b)推断**：通过新旧局面对比出"刚走子的阵营"自动翻面（支持吃子）；
- **开局库**：内置"桔库"（247 万条实战着法）。我方回合先查库，命中直接给出
  库内着法（含胜/和/负战绩，绿✓，零等待），未命中才走引擎——开局阶段建议即时且正统；
- **引擎**：独立启动一个 pikafish UCI 进程（复用项目内嵌二进制与 NNUE 权重，
  armv8/dotprod 两个变体随包内置、按 CPU 特性自动选择，无需选包），
  完成 `uci → uciok / isready → readyok` 握手后，按当前制式发送
  `position fen + go depth 12/20/24`（深度制，默认 20）或 `go movetime`（时间制，
  1/2/3/5/10/30 秒档，连线页单选热切换），解析
  `info … score cp/mate … pv` 与 `bestmove`，MultiPV 1-3 可调（默认 1 路，算力最全）；
  线程 = 核心数的一半、Hash 可在面板上调节（默认 256MB）；"闪电"按钮 `stop` 后
  立即采纳当前最优着法；启动失败自动重试一次，仍失败会在悬浮窗与通知栏
  显示具体原因（重新进入连线即可重试）；
- **悔棋**：服务端维护确认局面历史（上限 60 步），"悔棋"回退一步并暂停实时同步，
  "继续"恢复后自动与屏幕重新对齐；纯本地状态回退，不操作对弈 App；
- **悬浮窗**：始终使用 `TYPE_APPLICATION_OVERLAY`，可拖动、位置记忆；
  状态文字与按钮分列迷你棋盘左右两侧（面板高度只由棋盘决定，尽量少占屏幕高度）；
  迷你棋盘为**原版微缩样式**（共用主界面 chessboard.png 与 14 张棋子图，箭头复用主界面 ArrowShape），
  朝向**随动**（被识别 App 红在上时迷你棋盘也红在上，底部恒为我方侧），
  红/黑色条指示我方所在侧；点击迷你棋盘=切换候选着法（变招，引擎每次给出前 3 条候选）；
  我方回合显示"建议 X"+箭头：**蓝=暂定（仍在计算）→ 绿 ✓=定着（最佳着法已 1.2 秒未变或搜索结束）**；
  对方回合不画箭头，仅文字给出"若对方走X 我方应Y"的应对预案（对方未走时画我方应手会产生
  "我方吃我方"的误导）；识别中断/不稳定期间旧建议自动隐藏，恢复后重现。
- **性能**：抓帧快路径 220ms 只做帧差检测（静止画面零推理），慢路径 1400ms；
  识别间隔由节拍器自适应（上帧耗时×2 下限 1s，失败退避硬上限 8s；画面变化后
  burst 收紧到 300ms 级快速确认；走子动画等 200ms 停稳再识别），YOLO 在已知
  棋盘位置后只裁棋盘邻域推理（YOLOv5n fp16，约 3.8MB）；悬浮窗 FLAG_SECURE
  从录屏中整体剔除，抓帧全程无"隐藏面板"闪烁。

## 已知限制

- 竖屏布局假设：默认竖向截屏（市面象棋 App 基本竖屏）；横屏/旋转后识别会暂停并提示；
- 单步走子确认约需连续 3 帧稳定识别（主流机型约 1 秒级）；对局动画期间不确认；
- 引擎二进制仅含 arm64：x86_64 模拟器上无法启动分析引擎（悬浮窗会提示"引擎异常"），
  真机不受影响；
- **长时间连续使用会发热降频，识别与出着随之变慢**——单机全栈的固有代价，
  缓解办法见上文"性能与发热须知"；
- 不做（也不打算做）任何自动点击/自动走子。
